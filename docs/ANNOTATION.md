# 標註規範

人工標註是驗證偵測器的唯一依據，所以標註本身的一致性必須先被確認。

## 標註什麼

每個完整步態週期標註四個事件：

| 事件 | 定義 | 判準 |
|---|---|---|
| `IC` 左腳觸地 | 左腳第一次接觸地面的影格 | 逐幀前進，第一個看得出腳與地面接觸的影格 |
| `TO` 左腳離地 | 左腳最後一個仍與地面接觸的影格的下一格 | 逐幀前進，第一個看得出腳已離地的影格 |
| `IC` 右腳觸地 | 同上 | 同上 |
| `TO` 右腳離地 | 同上 | 同上 |

## 模糊影格的處理原則

1. **看不確定就標為 uncertain，不要猜。** 標成 uncertain 的影格會被排除在
   誤差統計之外；猜錯的標註會直接汙染 ground truth，比沒有標註更糟。
2. **不要放大畫面到超過 200%。** 放大到像素層級會讓標註者看到人眼在正常
   觀看距離下看不見的東西，這與規則「肉眼可見」的精神不符。
3. **不要參考系統的輸出。** 標註必須獨立進行，否則會產生確認偏誤，
   讓驗證失去意義。

## 一致性檢查

每批資料至少 20% 由兩位標註者獨立標註，計算：

- IC/TO 影格差的分佈（目標：中位數 0 格，95% 落在 ±1 格內）
- uncertain 標記的重疊率

若兩位標註者的一致性超過 ±1 格，代表判準本身有歧義，應該先修訂本文件，
再重新標註，而不是取平均值帶過。

## 格式

```json
{
  "video": "20260914_athlete03_side.mp4",
  "fps": 240.0,
  "annotator": "初始值",
  "events": [
    {"frame": 87,  "foot": "L", "kind": "IC", "certain": true},
    {"frame": 159, "foot": "L", "kind": "TO", "certain": true},
    {"frame": 166, "foot": "R", "kind": "IC", "certain": false}
  ]
}
```

影格編號從 0 起算，對應解碼後的影格序號。時間由 `frame / fps` 換算，
不另外記錄毫秒，避免兩個欄位不同步。
