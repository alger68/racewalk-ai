# 競走規則 TR54 與判定情境對照

本文件整理 World Athletics 競賽規則中與自動分析直接相關的條文，並列出每一條
對應到系統裡的哪個量。**規則原文以 World Athletics 官方最新版本為準**，
本文件是工程用的對照表，不是規則的權威來源。

## 兩條技術規則

### 1. 騰空（Loss of Contact）

競走是一種行進方式，行進中走者必須與地面保持接觸，使**人眼看不見**失去接觸。

裁判黃牌上的符號：`~`

對應到系統：`racewalk/gait/features.py` 的 `find_flights()`，量的是雙腳皆未
觸地的區間長度（毫秒）。

**這條規則的判定不是二元的。** 「可見」沒有官方數值定義，而菁英選手的騰空
時間本來就在 20–40 ms 之間。系統輸出毫秒數與不確定度，門檻
（`capability.DEFAULT_VISIBILITY_THRESHOLD_MS`，預設 40 ms）是可調參數，
必須以實驗與裁判對照來校準。

### 2. 彎膝（Bent Knee）

前導腳自**首次觸地瞬間**起，到通過**身體垂直位置**為止，膝關節必須保持伸直。

裁判黃牌上的符號：`>`

對應到系統：`features.min_knee_angle_during_support()`，區間的起點是 IC，
終點由 `features.vertical_support_index()` 判定（髖關節通過踝關節正上方）。

## 判罰流程

1. 裁判出示**黃牌**警示——這是提醒，不是判罰，不計入失格。
2. 裁判認定犯規時遞**紅卡**給主任裁判。
3. **三位不同裁判**各一張紅卡 → 失格（部分賽會改用罰時區 Penalty Zone）。

系統不模擬這個流程，也不累計紅卡。輸出只到「疑似，待人工複核」為止。

## 自動分析的界線

| 裁判做得到、系統做不到 | 原因 |
|---|---|
| 判定「肉眼可見」 | 這是感知判斷，沒有客觀定義 |
| 在集團中即時鎖定特定選手 | 遮擋時系統輸出 gap，不猜測 |
| 綜合整體動作型態下判斷 | 系統只量單一步伐的物理量 |

| 系統做得到、裁判做不到 | 價值 |
|---|---|
| 逐步伐量出騰空毫秒數 | 訓練時知道離邊界多遠 |
| 量出膝角到度 | 客觀、可追蹤趨勢 |
| 全程不漏看 | 裁判只能看到經過自己的片段 |

這張對照表就是本專案的定位：補裁判看不到的，不取代裁判看得到的。
